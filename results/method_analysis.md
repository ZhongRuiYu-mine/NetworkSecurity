## 5.0 先把「要什么」翻译成可执行的指标

需求原话是：

> 「那些实验 results 的数据能不能跑出来——A 方法的成功率怎么样、整体表现，
> 每一次攻击都是怎么反应的，它与其他几个的横向对比是什么表现，
> 进一步分析：A 在失败时候的原因是什么、成功的原因是什么、它更适合什么场景。B、C 同理。」

拆成六个可测量的量，并声明本章能给到什么程度：

| # | 需求 | 本章对应 | 能不能给 |
|---|---|---|---|
| 1 | 成功率 | §5.1 定义 + §5.2 总表 | ✅ 能给（机制层） |
| 2 | 整体表现 | §5.2、各方法 §x.2 | ✅ 能给 |
| 3 | 每一次攻击的反应 | §5.2 表 5-3、各方法 §x.3 | ✅ 能给 |
| 4 | 横向对比 | §5.2、§5.6 | ✅ 能给 |
| 5 | 失败/成功原因 | §5.7 归因分解、各方法 §x.5 | ✅ 能给 |
| 6 | 更适合什么场景 | 各方法 §x.6、§5.8 | ✅ 能给（含前提条件） |
| — | **策略层（MADDPG）的成功率** | §5.9 | ⚠️ **答不了**，见该节的说明 |

**一句话先给结论**：机制层的六项全部跑出来了，而且可复现；但
「A 方法成功率」如果指的是 **MADDPG 训练出来的智能体**的成功率，
那目前只能给一个**已崩塌**的数字。本章把这两层严格分开，不含混。

## 5.1 口径声明与「成功率」的定义

### 5.1.1 数据与阈值口径（协议 v1）

| 项 | 取值 |
|---|---|

| **自评污染** | 评估集与拟合集逐位重复 176/25000 = **0.70%**（协议目标 ≤1%；合并前的旧数据包是 14.02%） |
| 主阈值 | **良性分数 95% 分位**（α=0.05）；`fit()` 只喂良性流量、**不传标签** |
| 辅口径 | **F1 扫描**（用评估集标签选阈值）→ 只作为**乐观上界**并列引用，不作主数字 |

> F1 扫描阈值得到的，与本章口径不同源。本章数据取代它。

### 5.1.2 「成功率」的定义

**全仓库原来没有「成功率」的定义**——`src/utils/metrics.py` 的 docstring 里出现过
`success_rate` 这个词，但没有实现。所以本章必须先把它定义清楚，否则数字没有意义：

* **定义 1（机制层成功率，主用）**
  `= 该攻击类的样本中被检测器告警的比例`，等价于该类的**检出率 / Recall**。
  不含类别判定，是**机制层能力的干净度量**。
* **定义 2（端到端成功率，作为下界）**
  `= 告警 且 攻击类别判定正确`，只在真实攻击样本上统计。
* **退化下界（对照）**
  恒判 BENIGN 的规则成功率**按定义恒为 0**。任何 >0 的成功率都来自
  「检测器有信号 + 分工」，不是运气。

**为什么定义 2 目前只能当"下界"**：本仓库的三个检测器**只输出二值告警，不输出攻击类别**；
唯一的六分类头（MADDPG 的 class head）只有 IF 一版、且已崩塌（§5.9）。
所以端到端成功率只能用一个朴素的兜底规则算（告警 → 判成训练集里最多的攻击类 DoS），
它系统性偏低，**不代表机制层的真实上限**。

## 5.3 A 方法：Isolation Forest

### 5.3.1 成功率

| 口径 | 数值 |
|---|---|
| 机制层成功率（R，全类） | **0.3445** |
| F1 / ROC-AUC / PR-AUC | 0.4560 / 0.7327 / 0.5261 |
| FPR / FP‰ | 0.0579 / 57.9 |
| P@1% / P@0.1% | 0.0567 / 0.0059 |
| 失败归因分解（攻击 6453 条） | 成功 1760 · 告警但判错 463 · **双重失败 4230** |

### 5.3.2 整体表现

四个机制里**最弱的一个**：F1 0.4560 只比"什么都不做"的 0.4103 高 0.0457，
ROC-AUC 0.7327 也是最低。它的**误报控制其实是最好的**（FPR 0.0579，四个里最低），
代价是召回只有 0.3445——**它是靠"少告警"换来低误报，不是靠"看得准"**。

### 5.3.3 每一次攻击的反应

* **DoS：唯一像样的反应**。0.6009 告警率，分数中位数 0.6090 刚好压过阈值 0.5333（1.14 倍）。
* **DDoS：几乎没有反应**。告警率 0.1861，分数中位数 **0.4954 竟然低于阈值 0.5333**——
  也就是说"典型 DDoS 流量"在 IF 眼里**比阈值还正常**。这是 §5.3.5 失败原因的核心证据。
* **PortScan / Other：零反应**（0.0000）。分数中位数 0.3508 / 0.3688，比良性中位数 0.3572 还低或持平。
* **WebAttack：0.0101**（99 条里只有 1 条越过阈值）。

### 5.3.4 横向对比

| 对比项 | A `if` | 其他机制最好者 | 差距 |
|---|---|---|---|
| F1 | 0.4560 | 0.6521（`ae_paper`） | **−0.1961** |
| ROC-AUC | 0.7327 | 0.8474（`ae_paper`） | −0.1147 |
| 召回 | 0.3445 | 0.5800（`autoencoder`） | **−0.2355** |
| 误报 FPR | **0.0579**（最优） | 0.0958（`kalman_frozen`） | **−0.0379（A 赢）** |
| 拟合耗时 | 3.1 s（第三快） | **2.63 s**（`kalman_frozen`） | A 输 0.47 s；但比 `ae_paper` **快 193×** |
| 推理耗时 | 0.252 s | 1.223 s（`kalman`）/ 0.029 s（`autoencoder`） | 居中 |
| DDoS 检出 | 0.1861 | 0.6746（`kalman_frozen`） | **−0.4885（最大短板）** |
| PortScan 检出 | 0.0000 | 0.1036（`autoencoder`） | −0.1036 |

A 只赢一栏：**误报最低**；拟合耗时排第二（比 B 慢 0.47 s，但仍属"秒级"一档，
比 C⁺ 快 193 倍）。其余全输，其中 DDoS 一项差距最大（差 0.49）。

### 5.3.5 失败的原因是什么

**(1) 打分函数的动态范围被"压扁"了——这是根因。**
IF 的原始分数是 `-score_samples`，数值区间实测只有 **0.3302 ~ 0.7439**，全距 0.41；
阈值 0.5333 落在这个窄带的正中间。后果是良性与攻击的分数**大量重叠**：
良性中位数 0.3572、DDoS 中位数 0.4954、WebAttack 0.3645、Other 0.3688。
**四类的"典型值"挤在 0.35~0.50 这一小段里**，任何阈值都必然大量漏报或大量误报。

> 注意：IF 的分数是**路径长度**统计量，判据不直接依赖各特征的具体量纲，
> 所以平台那步 min–max 归一化**不是**它变弱的原因（这点和 AE 相反，见 §5.5.5）。
> 它的弱来自**算法本身在 78 维高维空间里对"攻击只是 benign 的轻微偏移"这类样本不敏感**——
> 随机切分要很多次才能把这种点隔离出来，而 `max_samples=256` 又把子样本压得很小，
> 进一步压平了路径长度的差异。

**(2) 「成功」为什么还能有 0.3445？**
因为 DoS 这一族在特征上偏移足够大（DoS 是洪泛/慢速攻击，包长与 IAT 统计量偏离良性很远），
IF 对**幅度型异常**仍然有效。所以 A 的成功**集中在 DoS 一族**，不是全面有效。

**(3) 归因分解说明了什么。**
6453 条攻击里 **4230 条（65.6%）是"双重失败"**——检测器没告警、判定也不可能对。
这是四个机制里最高的一档，与它的最低召回完全一致。
`告警但判错 463` 条是兜底规则的锅（§5.1.2），不是 IF 的锅。

### 5.3.6 它更适合什么场景

| 适合 | 理由 |
|---|---|
| **快速预筛 / 第一道粗筛** | 拟合 3.1 s、推理 0.252 s；先把明显异常挑出来交下游 |
| **误报预算极紧的场合** | FPR 0.0579 为四机制最低，FP‰ 57.9 |
| **特征未做归一化的场合** | IF 对逐特征单调变换不变，不依赖量纲，是它相对 AE 的结构性优势 |
| **集成里的一个成员** | 弱相关的基础模型仍有集成价值，但**不能当主判据** |
| **需要"幅度型异常"告警的场合** | 对 DoS 这类剧烈偏移有效（0.6009） |

| 不适合 | 理由 |
|---|---|
| **作为 CICIDS2017 的唯一检测器** | F1 只比 `null` 高 0.0457 |
| **DDoS / PortScan / 暴力破解防护** | 检出 0.1861 / 0.0000 / 0.0000 |
| **需要对分数做阈值/风险分级的场合** | 分数动态范围只有 0.41，分不出等级 |

## 5.4 B 方法：Kalman Filter

### 5.4.1 成功率

| 口径 | `kalman_frozen` | `kalman_decay` |
|---|---|---|
| 机制层成功率（R） | **0.5205** | 0.5168 |
| F1 | 0.5797 | 0.5764 |
| ROC-AUC / PR-AUC | 0.7841 / 0.5520 | 0.7795 / 0.5472 |
| FPR / FP‰ | 0.0958 / 95.8 | 0.0962 / 96.2 |
| P@1% / P@0.1% | 0.0521 / 0.0054 | 0.0515 / 0.0053 |
| 失败归因分解（攻击 6453 条） | 成功 1679 · 告警但判错 1680 · **双重失败 3094** | — |

> 两个模式数字几乎相同（F1 差 0.0033），说明在 CICIDS2017 这种**逐条 i.i.d.**
> 的表格流量上，**"基线跟不跟随"没有区别**——时序跟踪能力用不上。
> 代码注释里给的推荐是 `decay`，但**实测 `frozen` 略好**，对外报告应统一用 `frozen`
> 以与 IF / AE 的"只在良性上拟合、不更新"设定公平对齐。

### 5.4.2 整体表现

**中游，但形状与 A 完全不同**：召回 0.5205（比 A 高 0.176）却付出 FPR 0.0958
（比 A 高 0.038）的代价。它是四个机制里**误报最高**的一个：每 1000 条良性流量
误报 95.8 条，P@1% 只有 0.0521——**校正到线上 1% 攻击占比后，它报出来的警报
只有 5% 是真的**。

  扫描流量包小、速率低，逐维新息反而比良性波动更小。
* **WebAttack 0.0000 / Other 0.0000**，分数中位数 0.2272 / 0.3479，均低于良性水平。

### 5.4.5 失败的原因是什么

**(1) 阈值是按「Monday 良性」标定的，用到周二~周五就漂了——这是根因。**
主阈值的定义是「良性分数 95% 分位」，按设计它在良性上的误报率应当 ≈5%。
但**实测评估集 FPR = 0.0958**，也就是**接近设计值的两倍**。
这不是代码写错，而是**跨天分布漂移**：阈值是在 `X_normal_train`（Monday 60000 条）上标定的，
评估集的良性流量来自周二~周五，**它们的分数系统性地高于 Monday**，于是"95% 分位"这个名字
在评估集上名不副实。同一现象在 C⁺ 上有更细的证据（§5.5.5）：按天重标定阈值差 3.1 倍，
Wednesday 实测 FPR 0.1070 vs 设计 0.05。

**(2) 阈值方向与"最优"相反，说明这条分位规则在 Kalman 上是过度保守的。**
F1 扫描给出的最优阈值是 **0.72309**，比主阈值 **2.33629 低了 3.2 倍**：
把阈值放低，召回从 0.5205 跳到 0.7930，F1 从 0.5797 涨到 0.6652（+0.0855，四机制里第二大），
代价是 FPR 从 0.0958 升到 0.2057（**四机制里最优阈值处误报最高**）。
换言之：**同一批分数，阈值一动，排名就变**——B 的主口径排名（第 3）
并不能说明它的判别能力差，只说明**它的分位阈值选错了方向**。

> 对照：AE 族的方向正好相反。`ae_paper` 的最优 F1 阈值 **4.21303 高于**主阈值 2.42414
> （`ae_repro` 里 percentile 2.3092 < best_f1 3.6312，同样偏高），
> 放高阈值使 F1 从 0.6500 只涨到 0.6775（+0.0254），**涨幅最小**。
> **"阈值该往哪边调"在四个机制上都不一样**，这本身就是"不能只报一个阈值点的数字"的证据。

**(2) 为什么 PortScan / WebAttack / Other 完全看不到。**
Kalman 的判据是「这帧流量是否偏离**当前正常行为估计**」。
PortScan 的单流特征（小包、短连接）在逐维新息上**比良性还平稳**，
所以分数中位数 0.0154。这类攻击的异常性体现在**跨流的聚合模式**（同一源 IP 扫很多端口），
而 Kalman 是**逐条流、逐维**处理的，结构上看不到聚合模式。
这正是"状态估计类方法"的固有局限，不是调参能救的。

**(3) 「成功」为什么能有 0.5205？**
DDoS/DoS 是**幅度型**攻击——洪泛会让包速率、字节速率维度剧烈偏离基线，
逐维新息 NIS 立刻放大（DDoS 中位数 3.51，是良性的 14.7 倍）。
所以 B 的成功同样**集中在 DDoS/DoS**，与 A 的成败模式同构，只是幅度更清晰。

**(4) 归因分解：`告警但判错 1680` 条，占告警攻击的 50%。**
1679 成功 + 1680 告警但判错——**几乎一半的告警被判到了错误类别上**。
但这个数字**不能怪 Kalman**：判类是那条兜底常量规则干的（§5.1.2）。
真正属于 B 的问题是 **3094 条双重失败（47.9%）**。

## 5.5 C 方法：Autoencoder

C 有两版，必须分开讲，**它们的强弱项不一样**：

* **C（平台内置 `AutoencoderDetector`）**：78→64→32→8，30 轮，ReLU，逐维残差
* **C⁺（论文复现版 `ae_paper`）**：78→32→16→8→4 编码器 + 浅层解码器，BN + LeakyReLU + dropout 0.1，

### 5.5.5 成功的原因是什么 / 失败的原因是什么

**成功原因**

1. **判据与攻击的物理机制对齐**。自编码器衡量"这条流能否被良性流形重建"；
   DDoS/DoS 的包速率、字节速率、IAT 统计量远超良性流形的表达范围，
   重构残差自然爆炸（DDoS 4.7 倍、DoS 4.7~86.7 倍阈值）。
2. **只喂良性训练 + 逐特征残差**，不需要攻击样本，也不假设分布形状。
3. **瓶颈压缩（78→4）强迫模型只学良性的低维流形**，攻击落在流形外。
4. **打分口径的选择被实验证明是对的**：`ae_repro` 消融显示
   `log1p+z-score` 输入会把 ROC-AUC 从 0.8451 砸到 **0.6461**（−0.1990）——
   平台已按论文 Eq.1 做过 min–max，**再标准化一次会压掉攻击的幅度信息**。
   这解释了为什么 C 族在同样的数据上比 A/B 更稳。

**失败原因**

1. **阈值是真正的瓶颈，不是模型**。`ae_repro` REPORT.md §6 的原话：
   当天重标定阈值 **2.1139 ~ 6.4728（相差 3.1 倍）**，
   说明"一天标定、多天使用"必然让某些天的实际误报率远超设计值
   （Wednesday 实测 0.1070 vs 设计 0.05）。
   > ⚠️ 报告里必须同时写明：那张表的「当天误报率 ≈0.05」是**构造出来的**
   > （阈值就是当天良性分数的 95% 分位），它**不构成**"阈值可校准"的证据。
2. **弱项是特定攻击族，且原因可解释**：PortScan / WebAttack / 暴力破解
   在特征空间里离 Monday 良性太近（WebAttack 中位数 0.6275 vs 良性 0.2416，只差 2.6 倍），
   重构误差不足以越过阈值。**这是"训练时没见过攻击"的必然代价**，不是实现 bug。
3. **`Other` 一族 100% 漏检**，而它 100% 是 FTP/SSH-Patator 暴力破解——
   **报告里必须如实写这一句**，否则"Other 检出率≈0"会被误读成"杂项不重要"。
4. **排序能力与可解释性存在取舍**（`ae_repro` REPORT.md §6）：
   论文字面实现（原始 MSE 打分）**AUC 0.8618 / PR-AUC 0.7495 反而更高**，
   但它的逐特征残差没有可比量纲，**逐特征归因和 embedding 都会失真**，
   且对训练轮数敏感（76→181 轮时 PR-AUC 从 0.621 掉到 0.556）。
   主配置（逐特征标准化残差）在 15~250 轮之间几乎不漂移。
   → **只比 AUC/PR-AUC 应该用字面实现；要让 critic 拿到有方向的残差则用主配置。**

### 5.5.6 它更适合什么场景

| 适合 | 理由 |
|---|---|
| **DoS / DDoS 检测主力** | 0.6845 / 0.6685，且分数分离度远好于 A/B |

   「**它的判别能力被分位阈值低估了，但它的误报问题是真的**」。
   它的独特价值是 **DDoS 检出第一（0.6746）** 和**天然流式**。
3. **C（Autoencoder）族整体最强，且是唯一"可解释 + 可调优"的一族**。

## 5.7 失败归因分解：是谁的锅

### 表 5-5　攻击样本的四类互斥分解（合计 = 6453）

| 机制 | 成功（告警∩判对） | 告警但判错 | 漏报但判对 | **双重失败** | 双重失败占比 |
|---|---|---|---|---|---|
| A `if` | 1760 | 463 | 0 | **4230** | **65.6%** |
| B `kalman_frozen` | 1679 | 1680 | 0 | **3094** | **47.9%** |
| C `autoencoder` | 2005 | 1738 | 0 | **2710** | **42.0%** |
| C⁺ `ae_paper` | 2009 | 1662 | 0 | **2782** | **43.1%** |
| `null` | 0 | 0 | 0 | 6453 | 100% |

**怎么读这张表**：

* `漏报但判对 = 0` 对**所有**机制都成立，这是**兜底规则的构造性产物**（不告警就判
  BENIGN，而这些都是攻击行）——**不是发现，必须声明**，否则会被误读成"判定层从不出错"。
* `告警但判错` 一列（463 / 1680 / 1738 / 1662）**主要是判定层的锅**，不是检测器的锅。
  证据：这条规则把告警一律判成 DoS，所以只有 DoS 那个类别能"判对"，
  其他族即使检测器完美告警，也一定落到这一列。
* 因此**检测器的真实责任在 `双重失败` 一列**，
  它等于 `攻击数 × (1 − 该类检出率)` 的汇总。C 族最低（42.0%），A 最高（65.6%）。

### 判定层为什么退化（这是本章最该写清的一条）

`scripts/eval_policy_sweep.py` 用了三个**不训练**的判定规则来分离"机制层"与"判定层"：

| 判定规则 | 定义 | 全局成功率（÷6453） | 逐类成功率 |
|---|---|---|---|
| `detector` | 告警 → 训练集里最多的攻击类（DoS）；否则 BENIGN | A 0.2727 / B 0.2602 / C 0.3107 / C⁺ 0.3113 | **只有 DoS 一栏非零**，且等于 DoS 检出率（0.6009 / 0.5732 / 0.6845 / 0.6859） |
| `specialist` | 每个智能体告警 → 自己的 `focus` 类，5 体多数投票 | A 0.0716 / B 0.2596 / C 0.2572 / C⁺ 0.2569 | **只有 DDoS 一栏非零**，且等于 DDoS 检出率（0.1861 / 0.6746 / 0.6685 / 0.6677） |
| `benign_only` | 恒判 BENIGN | 全部 **0.0000**（干净下界） | 全部 0.0000 |

**为什么全局成功率正好等于某一族的"检出数 ÷ 攻击总数"**：
`specialist` 的 5 个 focus 是 `[DDoS, PortScan, DoS, WebAttack, DDoS]`——
**DDoS 占 2 席**，所以只要告警，多数票必然落在 DDoS 上
（以 `if` 为例：0.1861×2483 = 462 条，462/6453 = 0.0716 ✓）；
`detector` 的兜底类是先验最多的 DoS，所以必然落在 DoS 上
（0.6009×2929 = 1760，1760/6453 = 0.2727 ✓）。
**两条规则都不是分类器，只是"常量输出 + 谁嗓门大"。**
这解释了表 5-3 里端到端成功率**除 DoS 外整列为 0** 的现象。

> 早期版本还尝试过 `oracle`（完美检测器）和 `prior`（先验攻击类）两个规则，
> 实测它们输出的预测序列与常量规则**逐位相同**，只有 flag 不同——
> 那种"完美检测器上界"是假的，**已删除**。
> 现在**不构造假的完美上界**；要把机制层与判定层分开看，直接用表 5-1 的机制层指标。

## 5.10 本章结论（五条）

1. **成功率需要重新定义**。本章采用「机制层成功率 = 该类被告警的比例」为主口径，
   「端到端成功率 = 告警且判对」为下界，并以恒判 BENIGN（恒为 0）作对照。
   **原报告里"成功率"没有定义，这是必须先补的一环。**

2. **机制层表现排序稳定且可复现**：
   `ae_paper`(F1 0.6521) > `autoencoder`(0.6412) > `kalman_frozen`(0.5797) > `if`(0.4560)，
   且 `if` 只比"什么都不做"（0.4103）高 0.0457。

3. **四个机制的成功都只集中在 DDoS/DoS 两族**（`if` 的 DDoS 只有 0.1861，
   但它在 DoS 上到 0.6009；其余三个机制在 DDoS/DoS 上都落在 0.57~0.69）；
   **PortScan / WebAttack / 暴力破解是共同盲区**。其中 `Other` 在评估集里
   **100% 是 FTP/SSH-Patator 暴力破解，检出率 0.0000**——报告必须如实写。
   唯一存在互补性的是 PortScan（只有 `autoencoder` 有信号，0.1036）。

4. **失败原因已定位到具体机制**：
   A 是"分数动态范围被压扁"（0.33~0.74，四类典型值挤在 0.35~0.50）；
   B 是"重尾分布 + 跨天漂移，分位阈值既偏高又放错位置"（F1 扫描能补 +0.0855，
   且**最优阈值处误报 0.2057 仍是四机制最高**）；
   C 是"阈值而非模型"（跨天最优阈值差 3.1 倍，Wednesday 实测 FPR 0.1070 vs 设计 0.05）。
   共同盲区的原因也清楚：**PortScan/WebAttack 在流特征空间里离良性太近**
   （WebAttack 分数只比良性高 2.6 倍），而 Kalman 逐流处理看不到聚合模式，
   IF 在高维下对轻微偏移不敏感。

5. **策略层（MADDPG）目前给不出可信的成功率**：唯一训练过的 IF 策略 5 个智能体
   全部塌缩（投票准确率 0.0754、Kappa −0.0219）。这是**训练失败**，不是方法结论；
   补跑策略训练是把它变成结论的唯一途径。
